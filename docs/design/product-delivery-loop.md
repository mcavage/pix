# One product-delivery loop

Pix supports both an understood patch and a product outcome. `deliver` selects
between them by the requested outcome, not diff size. A product requires framing,
architecture, delegated implementation and acceptance of the integrated experience.
`plan`, `build` and `ship` enter stages of that same loop; they do not each create a
new plan, repeat full tests and demand another clean review.

For product work the main agent owns intent, architecture decisions and integration.
Product/architecture challenges precede dependent implementation; design or DX
covers the actual interface. Workers receive caller-sized tasks with explicit
scope, interfaces and checks. Independent tasks run in separate worktrees. Model
choices remain explicit environment bindings; a role name does not establish cost
or capability. The implementation worker may edit existing files within its task.
The unique report-path rule prevents report collisions, not ordinary source edits.

The integrated candidate receives executed journey evidence and independent QA,
security and interface assessments at the affected scope. One final cross-vendor
review challenges the code and evidence. Findings return to the implementer;
changed evidence is rerun and independently dispositioned. Successful child exit,
unit-test count, screenshots and a PR link are not substitutes for product acceptance.
A deployed release additionally needs a real probe at its authorized release target.

The existing subagent runtime is a process/usage boundary, not a product state
machine. `max_turns` is a prompt hint, while idle/wall limits are executable.
Compaction continuation uses durable in-progress todos or a length stop; it is not
proof that all product criteria were satisfied. Files under `.pi-agent/deliver/`
record progress and evidence. Do not claim enforcement for prose alone.

Failed child results retain observed models, elapsed time and usage in the parent
text as well as structured details. Partial source is preserved and inspected;
neither failure nor successful exit proves candidate correctness. A budget refusal
must remain distinct from actual charged spend, and unknown usage is not zero.

Memory project lookup uses argument-vector Git execution so workspace names remain
literal. Recall remains append-only to preserve prefix caching; capture remains
explicit by default. Neither change introduces a second inference router or rate table.

Validation distinguishes three levels: packaging checks establish reachable
references; scripted child/Gateway tests establish runtime behavior; a live,
independently graded product run establishes model adherence. Passing the first two
must not be presented as proof of the third or superiority over native agents.
